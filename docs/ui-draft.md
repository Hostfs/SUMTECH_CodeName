# '내 옷장' 서비스 기획·UI/UX 초안

> 팀 논의용 초안입니다. 가정은 **[가정]**으로 표시했으며, 구현은 포함하지 않습니다.

---

## ① 디자인 콘셉트

옷 사진이 주인공인 밝고 조용한 옷장을 지향합니다. 아이보리 바탕 위에 흰 카드를 얇은 선으로 정돈하고, 계절 포인트 컬러는 버튼·선택 상태·체크 등 꼭 필요한 곳에만 씁니다. 카드는 둥근 모서리(16~18px)와 넓은 여백을 쓰고, 그림자는 거의 쓰지 않습니다. 아이콘은 얇은 선형으로 통일합니다. 디자인 MD에서는 사진 중심 구성, 일관된 8px 간격 체계, 토큰 기반 색·글자 규칙만 가져오고, 파란색·검은 내비게이션·대형 홍보 섹션은 쓰지 않습니다.

## ② 전체 메뉴 구조

| 메뉴 | 역할 | 모바일 | 데스크톱 |
|---|---|---|---|
| **내 옷장** (기본 진입) | 옷 목록, 검색·필터·정렬, 위치 일괄 변경 | 하단 탭 1 | 상단 메뉴 1 |
| **보관함** | 옷장·서랍·상자 등 장소 관리, 장소별 옷 확인 | 하단 탭 2 | 상단 메뉴 2 |
| **옷 등록** | 사진 등록과 정보 입력 | 하단 중앙 + 버튼 | 우측 상단 버튼 |
| **코디** | 보유 옷으로 코디 구성·저장·목록 | 하단 탭 3 | 상단 메뉴 3 |
| **설정** | 테마(자동/봄/여름/가을/겨울) 선택 | 하단 탭 4 | 우측 상단 아이콘 |
| (하위) 옷 등록·수정, 의류 상세 | 메뉴 없이 목록·보관함에서 진입 | | |

- **[가정]** 모바일은 하단 탭 4개와 중앙 등록 버튼, 데스크톱은 밝은 상단 바(아이보리, 하단 얇은 구분선)로 구성합니다.

## ③ 화면별 구성안

### A. 내 옷장
- **상단:** 서비스명 '내 옷장', 검색창("이름·색상·위치로 검색"), [옷 등록] 버튼. 아래에 둥근 탭 칩 `전체 / 상의 / 하의 / 아우터 / 신발 / 기타`, 그 옆에 필터 버튼(종류·계절·색상·보관 위치)과 정렬(`최근 등록순`·`이름순`).
- **본문:** 사진 중심 카드 그리드(모바일 2열, 태블릿 3열, 데스크톱 4~5열). 카드는 정사각 사진(옷 전체가 보이도록 `contain` + 여백), 의류 이름, 위치 한 줄(예: `옷장 A · 서랍 2`, 미지정이면 `위치 미지정` 회색 배지).
- **하단:** 하단 탭. [선택] 버튼을 누르면 카드에 체크 표시가 생기고, 하단에 `n개 선택됨 · [위치 변경] [선택 해제]` 바가 올라옵니다.
- **이동:** 카드 → 의류 상세 / [옷 등록] → 옷 등록 / [위치 변경] → 장소 선택 시트 → 완료 시 목록 복귀 + "n개의 옷을 '옷장 A'로 옮겼어요" 안내.

### B. 옷 등록·수정
- **상단:** 뒤로가기, 제목 `옷 등록`(수정 시 `옷 정보 수정`).
- **본문:** 사진 영역(`사진 올리기` 버튼, 올린 뒤 미리보기와 `다시 선택`). 필수 항목은 이름, 종류, 색상, 계절(복수 선택 칩), 보관 위치(드롭다운, `미지정` 선택 가능). `자세한 정보 추가`를 펼치면 브랜드·사이즈·소재·메모(모두 선택).
- **하단:** 고정 버튼 `[저장]`, 보조 `[취소]`.
- **이동:** 저장 → 내 옷장(새 옷 카드 강조 + "등록했어요") / `이어서 등록` 선택 가능 **[가정]**. 취소 → 이전 화면.

### C. 의류 상세
- **상단:** 뒤로가기, 의류 이름, 더보기(⋯).
- **본문:** 큰 사진, 기본 정보(종류·색상·계절·브랜드·사이즈·소재·메모), 위치 카드(`보관 위치: 옷장 A › 서랍 2`를 큰 글씨로 강조), `세탁·관리 정보` 영역. 라벨 정보가 없으면 "등록된 관리 정보가 없어요. 세탁 라벨을 촬영해 추가할 수 있어요."를 보여 줍니다.
- **하단:** `[위치 변경]`(주요) `[수정]` `[삭제]`(보조, 삭제는 확인 창 "정말 삭제할까요? 코디에서도 빠져요.").
- **이동:** 위치 변경 → 장소 선택 시트 → 상세에 반영 / 수정 → 옷 수정 / 삭제 → 내 옷장.

### D. 보관함
- **상단:** 제목 `보관함`, [장소 추가] 버튼.
- **본문:** 장소 카드 목록(이름, 옷 개수, 대표 사진 3장 미리보기). **[가정]** 옷장 > 서랍 같은 하위 구조는 1단계 하위까지만 지원. 장소를 누르면 그 장소의 옷 목록이 열리고, `이름 수정`과 `옷 이동`(선택 후 다른 장소로)이 가능합니다.
- **하단:** 하단 탭. 장소 삭제 시 "이 장소의 옷 n개는 '미지정'으로 바뀌어요." 안내.
- **이동:** 장소 카드 → 장소 상세(옷 목록) → 옷 카드 → 의류 상세.

### E. 코디
- **상단:** 제목 `코디`, 탭 `만들기 / 저장한 코디`.
- **본문:** 위쪽에 코디 캔버스(선택한 옷이 상의·하의·아우터·신발·소품 순으로 한 화면에 정돈되어 배치됨. 자유 이동이 아닌 **고정 슬롯형** 제안), 아래쪽에 내 옷장에서 고르는 옷 목록(종류 칩으로 필터). 가상 착용은 하지 않습니다.
- **하단:** 코디 이름 입력, 메모 입력, `[코디 저장]`. 저장한 코디는 카드 목록으로 보이고, 상세에서 구성 옷을 누르면 의류 상세로 이동합니다.
- **이동:** 저장 → `저장한 코디` 탭("코디를 저장했어요").

### AI 확장 기능의 화면별 위치 (확장 단계)

| 기능 | 위치 | 사용자 이용 방식 |
|---|---|---|
| 사진에서 종류·색상 후보 | 옷 등록 | 사진 업로드 후 `정보 후보 보기` → 후보가 입력칸에 **미확정 상태**로 채워지고 사용자가 확인·수정 후 저장 |
| 상품 택 촬영 | 옷 등록 > 자세한 정보 | `택 촬영하기` → 읽은 브랜드·품번 표시, 제품 후보가 있으면 카드로 제시, 고른 것만 반영. 못 읽은 값은 `확인 필요` |
| 세탁 라벨 촬영 | 의류 상세 > 관리 정보 | `세탁 라벨 촬영` → 읽은 소재·관리법을 원문 사진과 함께 표시, `확인 필요`는 비워 둠, 사용자가 확정 |
| 보유 옷 코디 추천 | 코디 > 만들기 | `추천 받기` → 내 옷장의 옷만으로 조합 제안, 마음에 들면 캔버스로 불러와 수정·저장 |

- 보관 위치는 AI가 채우지 않고 항상 사용자가 지정합니다.

**대비 유의점 (대략 계산 기준):**
- 봄·여름은 밝은 색이라 어두운 글자가 안전합니다(여름 버튼에 흰 글자는 대비가 약 2:1로 부족).
- 가을 `#A47148`은 흰 글자 대비가 약 4.2:1로 작은 글씨 기준(4.5:1)에 못 미칩니다. 버튼은 굵게·크게 쓰고, 작은 글씨는 진한 파생색을 씁니다.
- 봄 기본색은 흰 배경 위에서 선이나 글자로 쓰면 묻히므로, 글자·아이콘 강조는 파생 진한색으로 합니다.

**테마 동작:**
- **자동:** 3~5월 봄, 6~8월 여름, 9~11월 가을, 12~2월 겨울 (현재 10월은 가을).
- 설정의 `화면 테마`는 `자동 / 봄 / 여름 / 가을 / 겨울` 칩으로 구성하고, 변경은 즉시 반영(저장 버튼 없음).
- 색만 바뀌고 검색어, 필터, 작성 중인 입력값은 유지합니다. 의류의 `계절` 필터와는 별개이며 설정 화면에 "화면 색상만 바뀌고 옷 정보는 바뀌지 않아요." 안내를 둡니다.
- 한 화면에는 현재 테마 색 하나와 같은 계열 보조색만 씁니다.

**타이포·간격 토큰 (제안):**
- 글꼴: Pretendard(없으면 system-ui) **[가정]**
- 제목 24px/600, 섹션 제목 18px/600, 본문 16px/400(줄간격 약 1.5), 보조 14px, 캡션 12px. 500 굵기는 쓰지 않습니다.
- 간격은 8px 단위(8·12·16·24·32), 카드 안쪽 16px, 카드 간격 12~16px, 카드 모서리 16px, 버튼 모서리는 알약형, 모바일 버튼 높이 48px 이상.

## ⑤ 대표 사용자 흐름

**1. 옷 등록**
1. 내 옷장에서 [옷 등록]
2. `사진 올리기`로 사진 선택, 미리보기 확인
3. 이름·종류·색상·계절 입력(위치를 모르면 `미지정`)
4. [저장]
5. 내 옷장에 새 카드가 표시됨

**2. 보관 위치 찾기·변경**
1. 내 옷장 검색창에 옷 이름 입력(또는 위치 필터)
2. 카드의 위치 표시로 바로 확인
3. 카드를 눌러 상세에서 큰 글씨 위치 확인
4. [위치 변경] → 장소 선택
5. 반영됨

일괄 변경: 목록에서 [선택]으로 여러 벌 체크 → [위치 변경] → 장소 선택 → "n개의 옷을 옮겼어요."

**3. 코디 저장**
1. 코디 탭 > 만들기
2. 아래 옷 목록에서 상의·하의·아우터 등을 탭해 캔버스에 배치
3. 코디 이름·메모 입력
4. [코디 저장]
5. `저장한 코디`에서 확인, 구성 옷을 누르면 의류 상세로 이동

## ⑦ 팀에서 결정할 사항

1. **데이터 저장 방식과 로그인 범위:** 기기 저장(빠름)과 계정·서버 저장(여러 기기 이용) 중 무엇으로 시작할지. 사진 저장 방식과 개발 난이도에 영향이 큽니다.
2. **보관 위치 구조:** 장소를 1단계(`옷장 A`)로 단순하게 할지, 2단계(`옷장 A › 서랍 2`)까지 둘지. 카드 표시와 일괄 변경 화면이 달라집니다.
3. **코디 화면 방식:** 고정 슬롯형(안정적, 구현 쉬움)과 자유 배치형(자유도 높음, 구현 부담) 중 선택. 이 초안은 고정 슬롯형을 제안합니다.
